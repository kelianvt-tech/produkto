# Third-party context, built 22 Oct 2026 (not deployed)

The 21 Oct one-off pull is now a module: `mvp/app/third_party.py`, tables `third_party_runs/_shopping/_web/_reviews` (db.py), tests `test_third_party.py` (8; full suite 306 pass, real `produkto.db` untouched).

**Switch:** off unless `PRODUKTO_THIRD_PARTY=1`. Admin-only page `/admin/third-party` (estimate, guard, Run button, what the agent sees) or `python3 third_party.py <domain> [--estimate|--facts]`. No schedule.

**Cost guard:** estimate first (Shopping $0.0044 × 20 × questions; web $0.0025 × 2 pages × 2 queries; Trustpilot $0.005 + $0.0005/review). Refuses if over the per-store cap (`PRODUKTO_THIRD_PARTY_CAP`, default $3), if the Apify account would be left with under $10 of its monthly limit, if the balance can't be read, or if a pull for that store is already running.

**Where the agent sees it:**
- Diagnose: each brief (`briefs.build` → `third_party`) carries Shopping status per question, name clashes, conflicting product counts. Goes into product-fix/FAQ draft input as research-only (`drafts._third_party`); writing rules unchanged.
- Citations: retailer/review/forum/video pages naming the brand, in the brief; retailer and review pages are also read for Missing facts (`offsite_facts.candidate_urls`, free).
- Feed: Product Data cards "Get your products into Google Shopping" and "Use one <unit> count for <product> everywhere" (`feed_check.cards`).
- Reviews: Trustpilot count/score/recent complaints in the brief; card "Answer what reviewers complain about".

## Limits
- Google matching is rough: a brand is recognised by its name written in the listing; product matching needs every title word.
- The "Helsinki Moisturiser review" search came back from a Portuguese-language proxy, mostly junk. English-speaking countries now send `languageCode=en`; untested on a real run.
- Conflict detection reads counts with units (items, foods, ml, g, oz, capsules…). Not yet tried on 5Strands, whose data isn't in the server copy.
